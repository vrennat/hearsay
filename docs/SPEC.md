---

Build a local macOS menu bar app, **Hearsay**, that records meetings and writes speaker-labelled transcripts as plain files to `~/Meetings`. Everything runs on the Mac: transcription, speaker detection, voice matching, cleanup, summaries. No audio or transcript text ever leaves the machine. The only network use is the first-run model download.

This is a rebuild of an existing app whose features grew one at a time over several months. You know the full feature set up front, so design for it from the start instead of bolting things on. Where this document says "measured" or "found", that is a real result from the old app on this Mac; trust it over your intuition.

## Hard constraints

- Swift Package, macOS 26+, Apple Silicon, Swift 6 toolchain in Swift 5 language mode. Three products: the app (`MeetingTranscriber` executable, installed as `Hearsay.app`), a CLI (`mtcli`), and a test target.
- Keep these names so existing permissions, settings and meetings carry over: bundle id `com.tannervass.meeting-transcriber`, executable `MeetingTranscriber`, log file `~/Library/Logs/MeetingTranscriber.log`, app folder `~/Meetings`.
- Keep the on-disk format readable by the existing Claude skill (`claude/skills/meeting-transcripts/SKILL.md`, symlinked into `~/.claude/skills`): the skill reads `index.md`, `index.jsonl`, each meeting's `transcript.md` (with front matter listing speakers, `named: true/false`, talk time, `cleaned_by:`), `transcript.raw.md`, `meeting.json` (`status`, `error`), `live.md`, and calls `mtcli speakers | rename | title | process | cleanup`. Existing meetings in `~/Meetings` must open in the new app without migration.
- Dependencies: FluidAudio (pin exactly; the streaming Parakeet and diarizer APIs change between releases, so read the checked-out source before using them) for Parakeet ASR, speaker diarization and CAM++ voice embeddings; WhisperKit (argmax-oss-swift) as the second engine. Apple FoundationModels for on-device summaries. No cloud APIs.
- Always build with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`. `xcode-select` on this Mac points at the Command Line Tools and mixing toolchains breaks the ArgmaxCore build.
- No sudo on this Mac. There are no virtual audio drivers. System audio must come from a Core Audio process tap, which only works in a signed `.app` with `NSAudioCaptureUsageDescription`. An unsigned `swift run` binary cannot record, so anything audio-related is tested through the installed app or through CLI commands fed a WAV file.
- The app is an accessory (`LSUIElement`): a menu bar ear icon, no Dock icon.

## Architecture

Split into three targets so most logic is testable without audio hardware:

- **MeetingCore**: file store, data models, Markdown renderer, transcribers, diarization, word-to-speaker attribution, echo removal, glossary, cleanup, titling, name inference, voiceprint, live transcriber, dictation transcriber, retention, audio compression, end-of-meeting detection logic, crash report scanning. Nothing in here touches a microphone or a window.
- **MeetingTranscriber**: the SwiftUI app. Mic capture, system audio tap, recording session, calendar lookup, call-app monitoring, sleep guard, notch pill, windows, settings, dictation controller, crash relaunch. Plus a small C target for the signal handlers and for turning Objective-C exceptions into Swift errors.
- **mtcli**: a thin CLI over MeetingCore so every pipeline stage can be run and checked on a WAV without the app.

Design `transcript.json` as the single source of truth. `transcript.md`, `transcript.raw.md`, `index.md` and `index.jsonl` are always regenerated from it plus `meeting.json`. Never let any code path edit the Markdown directly.

## Data on disk

One folder per meeting under `~/Meetings` (a `--root` flag overrides for tests; it is never saved to defaults). Seed `~/Meetings/CLAUDE.md` (a reading guide) and `~/Meetings/glossary.txt` only when missing, so a user's edits are never overwritten.

Per meeting:

- `meeting.json`: id, title, startedAt, endedAt, status (`recording | recorded | processing | done | failed`), error, engine, streams (kind `mic|system`, file, startOffset in seconds from meeting start, sampleRate, channels), speakerNames (id to name), echoCancellation, appVersion, attendees (from the calendar invite), me (your name within attendees), audioRemovedAt.
- `audio/mic.caf`, `audio/system.caf` while recording. Uncompressed CAF because it survives a crash (about 1.7 GB an hour). After transcription, re-encode each track to AAC `.m4a` at 64 kbps per channel, verify the length, repoint `meeting.json`, then delete the CAF.
- `transcript.json`: formatVersion, engine, diarizer, processedAt, speakers (id like `mic-1`/`sys-2`, stream, defaultLabel, talkSeconds, optional `voice` embedding), utterances (speaker, stream, start, end, text, words with start/end).
- `cleanup.json`: cleaned text per utterance plus the `sourceProcessedAt` it was made from. The renderer uses it only while that matches `transcript.json`, so reprocessing silently drops a stale cleanup. With a cleanup, `transcript.md` is the cleaned text and `transcript.raw.md` the verbatim.
- `live.md` and `live.json`: the live transcript, written every 2 s and on every rename, with each line's span and the live speaker names, so a crash keeps them. `meeting.json` is never touched while recording.

Default speaker labels are `Me`, `Room N` (mic stream) and `Remote N` (system stream).

## Recording

- **Mic** through AVAudioEngine. Apple voice processing (echo cancellation) is off by default: it stops Zoom and Meet from hearing the user and turns call audio down. Echo is removed from the transcript instead (see Echo filter).
- **System audio** through a Core Audio process tap. The tap only delivers buffers while some other app plays audio, so a recording with no call has no system stream until sound starts; `startOffset` keeps tracks aligned.
- A running tap blocks a call app from starting audio on the built-in mic (Zoom timed out every 14 s and sat on "Connecting..."; it worked fine on a Bluetooth headset). A tap created after the call app starts is fine. So: watch for a new app using the mic (Core Audio's per-process `IsRunningInput`), stop the tap, wait until that app has an input device (input scope of `kAudioProcessPropertyDevices`, at most 30 s), then rebuild the tap 0.5 s later. A blocked Zoom reads as running input with no input devices, which is how you tell it is still waiting. Match ignored bundle ids lowercased; `com.apple.CoreSpeech` (dictation) must be ignored or every dictation restarts the tap.
- Changing the audio device stops AVAudioEngine and silences the tap. Both must rebuild themselves on device changes, with a generation counter so an older restart chain stops when a newer one or `stop()` begins.
- With no mic buffer for 10 s while recording, show an orange warning in the pill and menu and post a notification; keep retrying; clear when buffers return.
- **Sleep**: stop the recording on `NSWorkspace.willSleepNotification`. Continuing after wake recorded unrelated room talk, and the mach host clock the writers use does not advance during sleep, so the gap looked like 108 s instead of 24 min.
- **Sleep guard** while recording: hold an idle-sleep assertion and turn off clamshell sleep through `IOPMrootDomain` (`kPMSetClamshellSleepState`, the same call Amphetamine uses; no root needed). Turn it back on only if you were the one who turned it off, and keep a defaults flag so a crash can be undone at next launch. The built-in mic is cut in hardware with the lid closed, so a closed lid records silence unless a headset mic is in use.
- **End detection**: never stop by itself (except with the lid closed). Instead ask "Meeting over?" through a notification when: the apps that used the mic have held no audio for 15 s; or the calendar event ended 2+ min ago and both the call and the room have been quiet for 60 s; or nothing from either for 5 min. Then wait 15 min before asking again. "Heard" means a buffer louder than about -46 dBFS: call apps play silence for the whole call, a quiet headset mic sat near -63 dBFS, office talk ran about -47 (90th percentile -34). Room talk keeps an in-person meeting from being prompted; the call-ended check ignores it.
- **Live transcript**: always on, no setting. Streaming Parakeet per stream plus a live diarizer. The Live window lists each live speaker (stream plus diarizer slot); clicking one, or a line's label, names it. On processing, hand each live name to the final speaker on the same stream whose utterances cover more than half of that live voice's time, best covered first, one name per speaker. Measured on 7 meetings: 1:1s and small calls matched one to one; on big calls, voices the final diarizer split differently stayed unnamed, which is acceptable.
- **Crash relaunch**: a C handler for SIGABRT, SIGTRAP, SIGSEGV, SIGBUS, SIGILL, SIGFPE spawns `open -n <bundle> --args --after-crash` (plus `--resume-recording` if recording), then lets the signal kill the process so the crash report is still written. Arm it 60 s after launch so a launch crash cannot loop; never for `--record-for` or `--root` runs. With `--resume-recording`, wait 3 s for the old process to release audio, then start a new meeting with the crashed meeting's title, attendees and `me`; recover and process the crashed one as usual. At launch, list `MeetingTranscriber-*.ips` crash reports newer than a saved date and post one notification (10 s after an `--after-crash` launch, since the report lands a few seconds late). No alternate signal stack, so a stack overflow does not relaunch. Wrap the Objective-C exceptions from installing the tap and starting the engine as Swift errors.
- At launch, mark meetings still in `recording` as interrupted and process what was captured.

## Post-call pipeline (also `mtcli process` and `mtcli import <wav>`)

1. Transcribe each track only if it has enough loud seconds: 3 or 5% of its length, whichever is more, capped at 20 and never more than a quarter of the track, where "loud" is 10 dB above the track's own noise floor, clamped to -70 to -46 dBFS (amended 2026-10-23; was 20 seconds or a quarter above a fixed -46). Whisper invents words ("Thank you.") on a near-silent call track; Parakeet does not. Parakeet is the default engine, Whisper the alternative.
2. Diarize each track separately. Attribute words to speakers by overlap.
3. **Echo filter.** Two cases. Speaker echo: the mic hears the call through the speakers. Room-on-call: you joined the call from a room, so the call carries the room back through the room's mic about 0.3 s after your mic hears it (measured 0.2 to 0.35 s). Compare the two tracks' 10 ms loudness in 1.5 s windows. Where they match, a copy 0.1+ s behind is the call's echo and its words go; otherwise the mic is hearing the speakers and the mic's words go. Windows that do not match fall back to dropping matching words from whichever stream was the echo within the last 3 windows (else the mic). Unrelated speech reaches the match level in 5 to 15% of windows at scattered lags, so count a window only when a neighbour also matches at a lag within 50 ms. Measured across all meetings: the three room-on-call meetings kept 368 to 1,005 such windows, one speaker-echo call 49, the rest 0 to 12. The live transcript does the same per window once both streams have audio 1 s past the window.
4. **Glossary** (`~/Meetings/glossary.txt`): spelling fixes for names and terms after either engine. Reprocessing applies edits.
5. **Cleanup** (setting `cleanup`, `mtcli cleanup`): remove fillers and back-to-back repeated words, in code. Do not use the on-device model for this. It was tried for misheard words and got about 3 of 114 fixes right on a 52-minute meeting: it swapped glossary names in for other names and changed ordinary words.
6. **Voice embeddings**: one CAM++ embedding per speaker from up to 60 s of its 2 s+ utterances that overlap no one. Stored in `transcript.json`.
7. **Speaker naming**, in priority order: names already in `meeting.json`; live names; then invite and voiceprint names fill speakers still unnamed with names not already used.
   - Voiceprint: built on the fly from mic speakers named with your first name in other meetings, one sample per meeting, best match wins. A mic voice is you at 0.6+ cosine similarity and 0.15 ahead of the next mic voice. Measured on 15 meetings: you scored 0.70 to 0.90 across headset and built-in mic, other mic voices 0.54 or less.
   - On a 1:1 invite (one other attendee, counted against your name since `me` can be missing) with exactly one other main voice on either stream, that voice gets the other name, so in-room 1:1s are named too. Without a voiceprint match, a 1:1 invite with one mic voice names it you. Voices under 5% of their stream's talk time do not count. A title word of 3+ letters that starts a first name is used as the nickname ("Rob / Tanner" names Robert "Rob").
8. **Title**: from the calendar event when there is one, else a date-time name. `mtcli title` and `mtcli rename` edit after the fact.
9. Compress audio, write `transcript.json`, render Markdown, reindex.
10. Reprocessing an older room-on-call meeting moves the room from `sys-*` to `mic-*` ids, so names typed for old ids may land on other voices; warn in the log.

## Calendar

Read events through EventKit, which sees the Google calendar added in Internet Accounts. Do not add a Google API client; one was tried and removed after EventKit picked the same event on every past meeting except one the pick rule explains. Rules: an event with a guest list you are not on counts only on a calendar where you are on other guest lists in the same 6 hours (keeps your own calendar's events that list only the other person, drops shared calendars like interview schedules). On a tie, an accepted event beats an unanswered one. Opening the menu looks up the current event at most once a minute for the title placeholder.

## Naming aids (suggestions only, never applied automatically)

- **Name hints** from how people address each other: "Hey Nate, how's it going?" or "what's next up, Priya?" points at the next voice (within 4 s, among the next 3 turns); "Thanks, Omar." at the voice before. A candidate is a capitalized first name from the invite or from names typed in any meeting. A cue counts only after a greeting or thanks that starts its sentence, or set off by a comma and ending a question or the turn, and not with retold-speech words ("said", "like", "told") in the 4 words before. Most votes win, then first heard. Measured on 90 meetings: about 21 cues, 9 of 11 on named speakers right. Show as "Sounds like Nate" with the quote, in the live name popover and under an empty name in the meeting window. `mtcli hints`.
- **Speaker summaries** from FoundationModels: one line per speaker, biggest talkers first, about 1 s each, not saved. Feed up to 5,000 characters of the speaker's longest turns; skip speakers under 60 words (with fewer, and an example phrase in the prompt, it repeated the example as the summary). It still sometimes names someone despite the prompt, so present it as a naming hint. `mtcli summaries`.

## Retention

Run at launch and every 24 h. Decide by `startedAt` age: past the transcript limit the folder goes to the Trash; past the audio limit, and only once `transcript.json` exists, delete `audio/` for good, empty `streams`, set `audioRemovedAt`. Skip meetings that are recording, processing or queued. `process` must refuse a meeting with `audioRemovedAt` before touching its status so it stays `done`. `mtcli retention --audio-days N --transcript-days N` lists the plan, `--apply` does it.

## Dictation (Settings → Dictation, default off)

Hold Right Option (or Right Command, or Fn) anywhere and talk; releasing pastes the text into the focused app. Another key pressed while holding cancels. A press under 0.3 s latches: listen until the next press of the key, other keys do not cancel, Esc does. Open the mic with a separate capture instance only while active. Streaming Parakeet shows words in a bubble near the bottom of the screen; on release the whole clip goes through batch Parakeet (its own instance so a meeting being transcribed does not block it), then the glossary and, with `cleanup` on, filler removal. Paste with a ⌘V `CGEvent` and restore the clipboard 0.5 s later, both `currentHostOnly` so Universal Clipboard never sends the text to another device; never restore a password manager item (`ConcealedType`). Needs Accessibility; without it leave the text on the clipboard. If the focused AX element is not a text field, text area, combo box or search field and its value cannot be set, still paste but leave the text on the clipboard and say so in the bubble for 2.5 s. Re-add the key monitors once `AXIsProcessTrusted` turns true. Save nothing; log lengths and timings only. `mtcli dictate <wav>` checks the path without the hotkey (measured: final text in 0.08 s on a 7 s clip, streaming about 2 s behind).
