# Hearsay: how the code meets the spec

`docs/SPEC.md` is the authority. This file records how the code meets it and why. Each entry is dated.

## Build

- 2026-10-23: Always `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift build` and `... swift test`. `xcode-select` points at the Command Line Tools; mixing toolchains breaks the build.
- 2026-10-27: `swift-tools-version: 6.3` (was 6.4 for `.macOS(.v27)`; the floor is now 26, and Tanner's work Mac has Xcode with Swift 6.3.3; `AudioLoader.convert` wraps `fill` in `withoutActuallyEscaping` because 6.3 rejects the capture). Earlier: 6.4, platforms `.macOS(.v27)` (amendment: macOS 27 on Apple Silicon), Swift 5 language mode. FluidAudio is added with `traits: []`, which drops its unused 8 MB NemoTextProcessing binary. See `docs/DEPENDENCIES.md` for the verified API survey.
- 2026-10-23: Pins are exact: FluidAudio `0.17.7`, swift-argument-parser `1.8.2`. Read `.build/checkouts/FluidAudio` before using any FluidAudio API; the README examples lag the source.

## Layout

- `Sources/HearsayCore/` — no microphone, no window. `Models/` (the four JSON files), `Store/` (folders, atomic writes, seed files), `Rendering/` (transcript, live and index Markdown), `Transcription/` (audio loading, Parakeet, segmentation), `Glossary/`, `Pipeline/` (import).
- `Sources/Hearsay/` — the app. A stub `main.swift` until step 2.
- `Sources/CrashSupport/` — C target for signal handlers. Empty stubs until step 8.
- `Sources/HearsayCLI/` — thin ArgumentParser CLI over HearsayCore: `import process cleanup compress rename title voices speakers hints retention dictate live-sim reindex lock unlock export`, every one with `--root`. Bare `hearsay` prints the help with one line per command. Run it with `swift run hearsay-cli ...`. `summaries <id>` (FoundationModels) prints one-line speaker summaries.
- 2026-10-23: **Amendment: Hearsay through and through.** App target and executable `Hearsay`, library `HearsayCore`, bundle id and logger subsystem `com.tannervass.hearsay`, log `~/Library/Logs/Hearsay.log`, CLI `hearsay`. The CLI's target is `HearsayCLI` and its product `hearsay-cli`, because APFS is case-insensitive: `Sources/hearsay` collides with `Sources/Hearsay`, and a `hearsay` binary would overwrite `Hearsay` in `.build`. The install script copies it to `~/.local/bin/hearsay`. `~/Meetings` and the file format are unchanged.
- `Tests/HearsayCoreTests/Fixtures/2026-10-01 0930 Fixture standup/` — a synthetic complete meeting folder (meeting, transcript, cleanup, live JSON plus live.md) with unknown keys and missing optionals. Reuse it; tests copy it into a temp root (`TestSupport.rootWithFixture`).
- 2026-10-23: `Tests/HearsayCoreTests/Fixtures/2026-09-15 1400 Old app sync/` imitates the old app's folder: `engine: "whisper"`, `echoCancellation`, `appVersion`, epoch `endedAt`, room-on-call `sys-*` speaker ids, `transcript.json` `formatVersion` 1 with no `voice`, no `stream` fields and `word` keys, a stale `cleanup.json`, `live.json`/`live.md`, no `audio/`. `OldFormatTests` loads, renders, reindexes and runs `VoiceBackfill` (`voices --apply`) on it. **It is derived from the spec's descriptions, not checked against a real old folder**; copy one from the earlier Mac into a scratch root and run `reindex` and `voices` to confirm.

## Data rules

- 2026-10-23: **Amendment: Parakeet is the only engine.** No WhisperKit dependency, no engine setting, no `--engine` flag. `engine` stays in `meeting.json` and `transcript.json` (always `parakeet`) so old folders decode. No `Transcriber` protocol: with one engine it would be dead flexibility; code uses `ParakeetTranscriber` directly.
- 2026-10-23: `transcript.json` is the single source of truth. `transcript.md`, `transcript.raw.md`, `index.md`, `index.jsonl` are always regenerated (`TranscriptRenderer.write`, `IndexRenderer.reindex`); no code path edits Markdown.
- 2026-10-23: A cleanup applies only when `cleanup.sourceProcessedAt` equals `transcript.processedAt` (within 0.5 ms, to survive millisecond rounding). A stale cleanup is ignored silently and `cleaned_by:` is omitted. `transcript.raw.md` is always verbatim. `cleaned_by:` shows `cleanup.method` (default `hearsay`).
- 2026-10-23: Every model decodes with `decodeIfPresent` and defaults, and ignores unknown keys, so old-app folders open without migration. Unknown `status` values read as `failed`. `Word` also accepts `word` for `text`. A missing `stream` is inferred from a `sys-` id prefix.
- 2026-10-23: Dates are ISO 8601 with fractional seconds on write; reads accept with or without fractions, and numeric epoch seconds.
- 2026-10-23: Every write is atomic: temp file in the same folder, then `replaceItemAt`/`moveItem`.
- 2026-10-23: The meeting id is the folder name, `yyyy-MM-dd HHmm <title slug>` (local time, up to 8 words / 60 chars, `-2` suffix on collision). `loadMeeting` overwrites any stored `id` with the folder name.
- 2026-10-23: `MeetingStore(root:)` takes an explicit root; it is never persisted. `prepare()` seeds `CLAUDE.md` and `glossary.txt` only when missing. During development always pass `--root` under scratch; never touch `~/Meetings`.
- 2026-10-23: `saveLive` writes `live.json` and `live.md` and never touches `meeting.json`.
- 2026-10-23: `named: true` means every main speaker has a name; a main speaker has at least 5% of its stream's talk time (spec's threshold for counting voices). The index shows named/main counts.
- 2026-10-23: Glossary: `wrong => Right` lines, `#` comments; whole-word, case-insensitive. A replacement with capitals is written as typed; an all-lowercase replacement copies the match's capitalisation. Applied to utterance text only; word timings keep the engine's spelling.

## FluidAudio 0.17.7 API used

- `AsrModels.downloadAndLoad(version: .v3)` downloads (first run only) and loads Parakeet TDT v3.
- `AsrManager(config: .default)` (an actor), then `loadModels(_ models: AsrModels)`.
- `transcribe(_ samples: [Float], decoderState: inout TdtDecoderState)` returns `ASRResult` (`text`, `tokenTimings: [TokenTiming]?`, `processingTime`). The README's `transcribe(samples)` without a decoder state does not exist in this release.
- `TdtDecoderState.make(decoderLayers: models.version.decoderLayers)` for a fresh state per clip.
- `buildWordTimings(from: [TokenTiming]) -> [WordTiming]` (`word`, `startTime`, `endTime`) merges SentencePiece pieces into words.
- Clips under 0.3 s throw `ASRError.invalidAudioData`; `ParakeetTranscriber` pads anything under 1 s with silence.
- Batch Parakeet returns one text for the whole clip; `Segmenter` splits words into utterances at 0.8 s pauses, sentence ends with a 0.3 s gap, or 30 s.

## Import

- 2026-10-23: `hearsay import` copies the source file unchanged to `audio/mic.<ext>` as stream `mic` (sample rate and channels recorded in `meeting.json`), decodes it with `AudioLoader` (AVAudioConverter to mono 16 kHz Float), transcribes, writes one speaker `mic-1` labelled `Me` (diarization is step 4), applies the glossary, renders and reindexes. AAC compression is step 3.

## Pipeline

- 2026-10-23: `ProcessPipeline.process(meetingID:store:options:)` is the one entry for the app (after a recording), `hearsay process` and `hearsay import` (which now copies the file in as `mic` and calls it). It refuses a meeting with `audioRemovedAt` before touching `status`. Order: decode each stream (first of each kind) with `AudioLoader`, gate, transcribe, echo filter, diarize and attribute per track, glossary, voice embeddings, naming, title, write `transcript.json` (`processedAt` rounded to ms) and `cleanup.json`, status `done`, then compress, then render and reindex. Compression runs after `transcript.json` is written (the spec lists it first) so a compression failure never costs the transcript; a failed stream keeps its original file and is logged. Any other error sets `failed` with `error`. `ProcessOptions` carries `PipelineEngines` (Parakeet, diarizer, CAM++ actors); its default is `PipelineEngines.shared`, the one set per process behind the app's queue, `process`, `import` and `voices`, so models load once per process. `LiveTranscriber` and `DictationTranscriber` own separate instances (spec: dictation must not wait on a meeting). Each engine loads lazily behind a `nil` check; two concurrent first calls on one actor could both load (actor reentrancy), which cannot happen while the queue processes one meeting at a time.
- 2026-10-23: **Interrupted and unusable meetings.** Spec: "mark meetings still in recording as interrupted and process what was captured." Decision: keep `error: "interrupted"` on a `done` meeting rather than add an `interrupted` field, because `meeting.json` `status`/`error` is what the reading guide and the skill already read, and a new field would need a format change for one bit. On failure the error reads `interrupted; <reason>`. No stream file at all: `failed`, `no audio captured`. Streams present but none past the loudness gate (missing, empty or quiet): `failed`, `no speech: ...`; no `transcript.json` is written and the models never load. A meeting that already has `transcript.json` but no audio file on disk is refused (`ProcessError.audioMissing`) before `status` changes, like retention's `audioRemovedAt`, so copying a folder without `audio/` never turns it `failed`. Failures are thrown as `ProcessError.failed(message)` whose description is exactly the stored `error`, because the app's `ProcessingQueue` writes `String(describing: error)` back into `meeting.json`.
- 2026-10-23: All times are meeting time: word, diarizer segment and loudness times are shifted by the stream's `startOffset`.
- 2026-10-23: `Loudness` is the one definition of "loud": 10 ms RMS frames above -46 dBFS (`Loudness.loudDBFS`). Gate: a track is transcribed only with `min(20 s, duration / 4)` loud seconds.
- 2026-10-23: Parakeet occasionally emits a stray "." in a long silence and FluidAudio's word merge glues it to the previous word, which then spans the whole pause ("first.." lasting 8.7 s on the `say` fixture) and hides the pause from `Segmenter`. The pipeline caps a word at 1.5 s and collapses doubled end punctuation.
- 2026-10-23: **Echo filter** (`Echo/EchoFilter.swift`), pure over the two meeting-time loudness curves and word lists. 1.5 s windows; Pearson correlation of the dB curves (floored at -70) at every lag from -0.5 to +0.5 s; a match needs r >= 0.75 and 0.3 s of loud frames in both slices. System 0.1+ s behind the mic: room-on-call, system words go; any other match (mic behind, or under 0.1 s): speaker echo, mic words go. A window counts only when window w-1 or w+1 matched at a lag within 50 ms. Confirmed window: every echo-stream word whose midpoint is in the window or the `lag` after it goes. Unconfirmed window: only echo-stream words whose normalised text the other stream has within 0.75 s go, the echo stream being the last confirmed one within 3 windows, else the mic. Batch (`run`) adds a look-ahead: with nothing in the previous 3 windows it takes the next confirmed window's stream within 3; without it the first seconds of the room-on-call fixture (before a full window of echo exists) dropped the mic's words instead of the system's. The live caller uses `match` per window range, then `decide` (no look-ahead) and `filter`. The 0.75 threshold and 0.75 s twin window are not measured on real meetings; tune them against the spec's window counts (368 to 1,005 room-on-call, 49 speaker echo, 0 to 12 others) once real meetings exist.
- 2026-10-23: **Diarization**: FluidAudio `OfflineDiarizerManager(config: .default)`, `prepareModels()`, `process(audio:)` per track; `TimedSpeakerSegment.speakerId/startTimeSeconds/endTimeSeconds`. If it throws, that track becomes one speaker and the error is logged. `transcript.diarizer` is `fluidaudio-offline`.
- 2026-10-23: **Attribution**: each word goes to the slot whose segments overlap it most, else the nearest segment. Runs of one slot are split by `Segmenter`. Ids `mic-N`/`sys-N` rank slots by attributed word time; `talkSeconds` is the sum of the speaker's utterance spans after the echo filter. Speakers with no words do not exist.
- 2026-10-23: **Default labels**: `Room N` for mic voices and `Remote N` for system voices, N from the id. A mic voice is labelled `Me` only when naming decides it is you (voiceprint, a name already equal to your first name, or the 1:1 one-mic-voice rule). Reason: in a room the loudest mic voice is often not you, and a wrong `Me` reads as fact.
- 2026-10-23: **Voice embeddings**: CAM++ (`CampPlusEmbedder.load()`, `embed(audio:)`, 192-d), one per speaker from its utterances of 2 s+ that overlap no other speaker on the same stream, longest first, up to 60 s, concatenated. Under 2 s of such audio the speaker gets no `voice`. The diarizer's 256-d WeSpeaker vectors are never used for matching.
- 2026-10-23: **Naming** writes into `meeting.json` `speakerNames`, so reprocessing keeps them (priority 1). Live names come from `live.json` through `LiveNameMapper.map(live:transcript:)` (the pipeline's interim `LiveNameMapping` was deleted at integration; `LiveNameMapper` had the dedicated tests and merges spans before measuring overlap). Your name is `meeting.me`, else `ProcessOptions.userName` (app setting, CLI `--me`); without either, voiceprint and 1:1 rules are skipped. Names are first names. Voiceprint samples: in each other meeting, the mic speaker with a voice whose name's first word is your first name (most talk time if several); best cosine over samples; you at 0.6+ and 0.15 ahead of the next mic voice with a voice. 1:1: the invite minus attendees with your first name leaves exactly one; main voices are 5%+ of their stream's talk time.
- 2026-10-23: **Title** (fallback rule, see "Titles" for the model): kept unless empty or a placeholder (`meeting`, `new meeting`, `untitled`, `untitled meeting`, `recording`, any case), else `yyyy-MM-dd HH:mm Meeting` in local time. The folder name never changes.
- 2026-10-23: **Cleanup** (`Cleanup/TextCleaner.swift`): fillers `um umm uh uhh er erm ah hmm hm mm` (a following capital is restored, a full stop moves to the word before) and back-to-back repeats of one word or a two-word phrase with no punctuation between copies. "Like" and "you know" stay: too often real words. A filler set off by commas takes the comma before it ("I, uh, think" -> "I think"). Dictation uses the same `TextCleaner.clean`. Setting `cleanup` is read from the `com.tannervass.hearsay` defaults suite (default on) by `ProcessOptions.fromDefaults`; the CLI uses `--cleanup/--no-cleanup`.
- 2026-10-23: **Compression**: AVAssetReader to AVAssetWriter, AAC at 64 kbps per channel, sample rate capped at 48 kHz, `audio/<kind>.m4a`. The output must be within 0.5 s of the source or it is deleted. `meeting.json` is repointed before the original is deleted. Streams already `.m4a` are untouched; any other extension (CAF, imported WAV) is compressed.
- 2026-10-23: Step 10: when reprocessing leaves fewer `sys-*` and more `mic-*` speakers than the old `transcript.json`, a warning lists the typed names that may now be on other voices.
- 2026-10-23: CLI: `process [--no-cleanup] [--no-compress] [--me]`, `cleanup`, `compress`, `rename <id> <speaker> <name>` (empty clears), `title <id> <title> | --suggest | --apply`, `voices [ids] [--me] [--apply]` (embeds missing voices in every meeting first, then names; prints the plan, `--apply` writes `transcript.json` voices and `meeting.json` names without changing `processedAt`). Struct names end in `Command` because `Process` and `Cleanup` collide with Foundation and the model.
- 2026-10-23: End-to-end fixture (`say -v Samantha` mic, `say -v Daniel` system at `startOffset` 2.0, ffmpeg): the diarizer gave one speaker per track; 1:1 invite named both ("Will" from the title "Will / Tanner"). With a 0.3 s, -6 dB copy of the mic mixed into the system track, every duplicated word was dropped from the system stream. Known miss, same before and after integration: the room-on-call case also drops the system's own last word ("...ready for a final" without "look."), whose midpoint falls in a confirmed window's lag tail.

## Titles

- 2026-10-23: **Amendment: titles from the on-device LLM** (`Titles/`). `TitleRules` is pure and tested: `isGeneric` (placeholders, the recorder's "Meeting Oct 23 09:30" and `Titler`'s date-time title, and any title that is empty or one of `sync`, `1:1`, `catch up`, `call`, `chat`, `check in`, `standup`, `huddle`... once modifier words like "weekly"/"quick"/"team" and attendee, `me` and typed speaker-name tokens are dropped, so "Will / Tanner" and "Catch up with Reese" count as generic); `prompt` (calendar title unless a recorder placeholder, attendees, date, duration, speakers by talk time, then `Name: text` lines of cleaned text when `cleanup.json` matches, capped at 1,500 words); `validate` (3-8 words, Title Case with small words like "and"/"of" allowed lowercase after the first, no quotes, last character a letter, digit or `)`, no month/weekday/"today"/year/`10/23`/ordinal/clock time, no "Meeting", not names only, not itself generic). Validation trims whitespace only and never repairs: a bad answer falls back rather than becoming a title the model did not write. `1.2`-style version numbers are allowed; "Q4 2026" is rejected as a date.
- 2026-10-23: `TitleGenerator.title` skips the model for `titleEditedByUser` and for a non-generic title; otherwise asks `OnDeviceTitleModel` (`SystemLanguageModel.default` availability via `SpeakerSummaries.unavailableReason`, `LanguageModelSession(model: .default, instructions:)`, `respond(to:generating: GeneratedTitle.self, options: GenerationOptions(temperature: 0.3, maximumResponseTokens: 60))`, `@Generable` struct with one `@Guide` string), behind a 20 s timeout that cancels and abandons the call. Unavailable, timeout, thrown or rejected all keep `Titler.title(for:)`; unavailability is logged once per process, other reasons once per meeting. `TitleModel` is a protocol only so tests can stub the model. Verified against the macOS 27 SDK by compiling.
- 2026-10-23: Pipeline: the title is chosen after `transcript.json` and `cleanup.json` are written (the model call can take seconds and never throws), saved with status `done`, and the closing reindex re-renders the Markdown. `ProcessOptions.titleModel` defaults to the on-device model.
- 2026-10-23: `titleEditedByUser` in `meeting.json` (decodes as false when missing) is set by `MeetingEdits.setTitle`, the one path for the window and `hearsay title <id> <title>`. `hearsay title <id> --suggest` always asks the model (even for a specific or hand-typed title) and prints the proposal, or "No title proposed: <reason>" with exit 1; `--apply` writes it through `MeetingEdits.applyGeneratedTitle`, which leaves `titleEditedByUser` unchanged.
- 2026-10-23: **Measured** on this Mac (M4 Pro, debug build, macOS 27), `SystemLanguageModel.default.availability` = `available`. `hearsay import` of a 27 s `say -v Samantha` monologue about a pricing page test, title "Sync", in a scratch root: the pipeline wrote "Pricing Page Redesign Strategy". `title --suggest` on it, 3 runs: same title each time, 0.96 / 0.53 / 0.52 s (first call includes model warm-up). On the 3-utterance fixture with its title set to "Sync": "Build Green Ship Today" rejected twice (`today` is a date word), then "Build Green Go" accepted, 0.56-1.43 s. With the fixture's own "Fixture standup" the model echoed "Fixture Standup" (2 words, rejected), so a short transcript gives the model little beyond the calendar title. Not measured: real meetings, or the 20 s timeout against the real model.

## Live, retention, hints, dictation

- 2026-10-23: **Live engines.** Per stream, `StreamingUnifiedAsrManager(config: UnifiedConfig(leftFrames: 70, chunkFrames: 7, rightFrames: 7))` (1120 ms tier; FluidAudio's doc says lower latency and better WER than the 2080 ms default), `loadModels()`, then per buffer `appendAudio(AVAudioPCMBuffer)` + `processBufferedAudio()` + `consumeTokenTimings()`; `finish()` at stop, `reset()` between meetings. Verified by build and `live-sim` against the 0.17.7 checkout.
- 2026-10-23: **Live diarizer is LS-EEND**, `LSEENDDiarizer().initialize(variant: .ami, stepSize: .step100ms, computeUnits: .cpuOnly)`, then `addAudio(_:sourceSampleRate: 16000)` + `process()`; segments read from `timeline.speakers[*].finalizedSegments + tentativeSegments`. Why not Sortformer: it caps at 4 speakers (big calls have more) and misses quiet speech; LS-EEND handles 10, is fastest on CPU (leaving the Neural Engine to Parakeet), and its local-only identities are all the live view needs. Its extra false alarms are absorbed by the >50% coverage rule in `LiveNameMapper`. LS-EEND has no lock; every call runs inside the `LiveTranscriber` actor, which serializes them.
- 2026-10-23: Live words are assembled from tokens by `LiveLineBuilder.appendTokens`, not `consumeWordTimings()`: the latter groups one drained batch at a time and split words across batches ("G reat", "la unch" in live-sim). Punctuation-only tokens do not extend a word's end, because they arrive a chunk late and hid a 5 s pause between two system turns.
- 2026-10-23: Live lines: each word goes to the diarizer slot overlapping it most (else the nearest segment within 1 s, else slot 0); lines break on a slot change, a 0.8 s pause or 30 s. Ids are `mic-N` / `sys-N` (1-based slot). Lines are rebuilt from all words on each save, so a tentative diarizer segment that later changes slot relabels its words.
- 2026-10-23: Buffers carry a meeting-time offset; the first one sets the stream's origin and later gaps are filled with silence so timings stay on the meeting clock (the tap delivers nothing while no app plays audio).
- 2026-10-23: `LiveTranscriber` saves `live.json` / `live.md` through `MeetingStore.saveLive` at most every 2 s while audio arrives, immediately on `renameSpeaker`, and at `finish`. It never writes `meeting.json`. `LiveTranscriber.shared` keeps its engines loaded for the life of the process; `LiveTranscriber()` is an independent instance.
- 2026-10-23: Live echo: `LiveEchoGate` releases 1.5 s window k only once both streams have audio to (k+1)·1.5 + 1 s. `LiveEchoTracker` then runs the pipeline's `EchoFilter.match` on that window's slice (window start to 1 s past its end), re-runs `EchoFilter.decide` over all windows so far (no look-ahead; window k-1 becomes confirmed once k matches), and `snapshot` applies `EchoFilter.filter`. Loudness is the shared `Loudness` curve. Tested with a 0.3 s, -6 dB system copy fed 100 ms at a time: every system word judged so far goes, every mic word stays. Without the batch look-ahead, a room-on-call meeting's first window can briefly drop mic words that have a twin until window 1 confirms it.
- 2026-10-23: `LiveNameMapper`: coverage = overlap of the final speaker's utterance spans with the live voice's line spans (each list merged first) over the live voice's time; candidates over 0.5 on the same stream, best coverage first, one name per live voice and per final speaker.
- 2026-10-23: `EndDetector` is a pure state machine on meeting-time seconds. Call-ended needs the call apps to have had audio first, then 15 s without; room talk does not reset it. Calendar: now ≥ end + 120 s and both streams' last loud buffer ≥ 60 s ago. Silence: 300 s since the last loud buffer on either stream (or since start). After any prompt, nothing for 900 s; then the same rules apply again.
- 2026-10-23: Retention: `RetentionPlan.make` is pure; age is `now - startedAt` in days, strictly greater than the limit. Past the transcript limit the folder is trashed even without `transcript.json`. Audio removal needs `transcript.json` and is skipped once `audioRemovedAt` is set. `queued` is a set the app passes (no stored status exists for it). `Retention.apply` re-reads each meeting and re-checks status before acting. `RetentionScheduler` runs at `start()` and every 24 h, reading settings at fire time; both limits 0 is a no-op.
- 2026-10-23: Name hints: turns are runs of one speaker's utterances. Greeting openers `hey hi hello morning welcome yo howdy good morning/afternoon/evening`; thanks openers `thanks thank you cheers` (point back). Vocative: previous token ends with a comma and the name ends the sentence, which ends with `?` or is the turn's last. Retold words in the 4 preceding words: `said says say like told tells tell asked asks`. Next voice: first other speaker among the next 3 turns, starting within 4 s of the cue turn's end; previous voice mirrors it. Candidates are first tokens of attendees and of every typed name (meeting and live), letters only, capitalized; the transcript word must be capitalized too.
- 2026-10-23: Dictation: `DictationTranscriber` owns its own `ParakeetTranscriber` (batch v3) and its own `StreamingUnifiedAsrManager`, so neither blocks a meeting. Clips under 0.3 s return empty text. Final text = Parakeet, glossary, then `TextCleaner.clean` when cleanup is on. Measured 2026-10-23 on an M4 Pro, debug build, `say` clip of 7.84 s: final text in 0.085–0.087 s (3 runs), streaming partials about 1.7 s behind real time (first word at 1.7 s).
- 2026-10-23: `CrashReports.list(in:since:)` matches `Hearsay-*.ips` by modification date. With no saved `lastCrashReportCheck` nothing is reported, so a first launch does not surface old crashes; the caller always calls `markChecked`.
- 2026-10-23: New tests use XCTest; the older suites use swift-testing. Both run under `swift test`, which prints two separate summaries: XCTest's `Executed N tests` and swift-testing's `Test run with N tests in M suites`. Read both; at integration: XCTest 65 tests in 18 classes, swift-testing 33 tests in 6 suites, 0 failures. After titling (2026-10-23): XCTest 92, swift-testing 34 in 6 suites, 0 failures.

## Recording

- 2026-10-23: App layout: `App/` (`HearsayApp` with `MenuBarExtra` in `.window` style so the Mic/Call chips can be coloured, `AppModel` observable, menu, placeholder Settings), `Recording/` (`RecordingSession` observable: elapsed, mic/system dBFS, per-stream `AudioLevel` with last-buffer and last-loud times for end detection, warnings, meeting id; `ProcessingQueue`), `Audio/` (`MicCapture`, `SystemTapCapture`, `CallAppMonitor`, Core Audio helpers), `System/` (`SleepGuard`, `Notifier`, `WindowInventory`). The pill, meeting and live windows read `AppModel.shared.session`.
- 2026-10-23: `meeting.json` is written twice per recording: `RecordingLifecycle.begin` (status `recording`, date-time placeholder title "Meeting Oct 23 09:30" until the calendar step, `engine: parakeet`, `echoCancellation: false`) and `RecordingLifecycle.finish` (`recorded`, `endedAt`, streams). A stream that never got a buffer is dropped and its empty CAF deleted; no stream at all sets error `no audio captured`.
- 2026-10-23: Each stream writes Float32 uncompressed CAF at the device's native rate and channel count (`CAFStreamWriter`); the pipeline downsamples. Tested: a copy of a CAF taken while the writer is still open reads back with frames, which is the crash-survival property. If a rebuilt device has another format the writer converts to the first one, because a CAF cannot change rate mid-file.
- 2026-10-23: `startOffset` = host seconds from meeting start (`HostClock.now()` before the folder is created) to the stream's first buffer timestamp (`AVAudioTime.hostTime`, `AudioTimeStamp.mHostTime`). After that, `StreamTimeline` pads any gap over 50 ms with silence, so the whole file stays on meeting time with one offset: the tap going quiet when nothing plays, device rebuilds and call-app pauses all become silence, not a shift. Mach host time does not advance during sleep, so this only holds because recording stops on `willSleepNotification`.
- 2026-10-23: Each writer saves `audio/<kind>.json` (the stream record) once at its first buffer and deletes it at stop, so crash recovery restores the real `startOffset` without touching `meeting.json` mid-recording. Without a sidecar the recovered offset is 0.
- 2026-10-23: Launch recovery (`RecordingLifecycle.recoverInterrupted`): every meeting still `recording` becomes `recorded` with error `interrupted`, streams from the CAFs and sidecars, `endedAt` from the newest CAF's modification date, then it is queued. `ProcessPipeline.process` keeps the `interrupted` error (see Pipeline, "Interrupted and unusable meetings").

## Encryption

- 2026-10-23: **Format** (`Crypto/EncryptedFile.swift`): `HSE1`, a 12-byte random base nonce, then chunks of up to 1 MiB plaintext, each AES-GCM ciphertext + 16-byte tag. Chunk i's nonce is the base nonce with i XORed into its last 8 bytes, big endian. Each chunk authenticates `HSE1 || index (u64 BE) || final (1 byte)` as associated data: the amendment only names the nonce counter, but without the final flag a file cut at a chunk boundary would decrypt "successfully" as a shorter file. Empty plaintext is one empty final chunk. Files stream with at most two chunks in memory (one chunk of look-ahead decides `final`), through a 0600 temp file renamed over the target. Tested: round trips at 0, 1, chunk-1, chunk, chunk+1, 2 chunks, 2 chunks+5 and 3 chunks+123 via files; a flipped ciphertext byte, a flipped tag, a wrong key, a file cut at a chunk boundary and two swapped chunks all fail.
- 2026-10-23: **Recordings key** (`Crypto/AudioKey.swift`): random 256-bit, generic password `com.tannervass.hearsay` / `audio-key` in the login (file-based) Keychain with `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`. Not the data-protection Keychain: that needs a `keychain-access-groups` entitlement, which the unsigned `swift run` CLI does not have. `AudioKeyStore` is injectable; test processes (`FileLog.isTestProcess`) default to `InMemoryAudioKeyStore`, so `swift test` never touches the Keychain. `HEARSAY_KEYCHAIN_SERVICE` overrides the service name, for scratch end-to-end runs only.
